# 咖啡馆 · 咖啡豆批次与饮品出单

咖啡馆经营管理系统：咖啡豆批次烘焙状态机、饮品菜单、桌台开台/清洁、收银台一条式点单出单（POS）。

## 技术栈

- 后端：Spring Boot 3.3 + Spring Data JPA + MySQL
- 前端：Vue 3 + Element Plus（顶部横向导航、棕色主题）

## 启动

```bash
sh start.sh        # 构建并启动（首次较慢，之后秒级）
sh stop.sh         # 停止
```

启动后访问前端地址（默认 http://127.0.0.1:8312 ）。

## 业务模块

1. **咖啡豆批次**：批次号唯一，烘焙状态机 待烘焙→烘焙中→已入库→已用完，只能逐级前进；入库时按重量折算批次余量（克），消耗扣到 0 自动转为已用完；每批次可追溯被哪些账单消耗过。
2. **饮品菜单**：名称唯一，价格>0，类别（意式/手冲/非咖啡），状态（在售/下架）；每个饮品可维护配方（豆种 + 每杯克数），配方只影响保存之后完成的账单。
3. **桌台**：桌号唯一，座位数>0，状态（空闲/占用/清洁中），仅空闲可开台。
4. **收银出单**：左选饮品→中点单流水→右结算；同一桌台仅允许一张未结账账单；账单状态机 制作中→已完成→已结账，结账后释放桌台。
5. **配方与消耗闭环**：账单「完成制作」时按当时保存的配方生成消耗流水（批次/克数/操作者/时间快照），只从「已入库」且有余量的批次分配，按最早入库顺序自动拆分、可跨批次；整单必须全量满足，否则一颗不扣、账单保持「制作中」。账单明细固化饮品名与单价快照，历史账单不随后续调价/改配方而改变。点单时库存不足的饮品会置灰并提示缺哪种豆、缺多少。

## 验证

后端含集成测试（`backend/src/test/java/com/cafe/house/ConsumptionFlowTest.java`，H2 MySQL 模式），
覆盖：完成时扣减与快照、跨批次 FIFO 拆分、库存不足整单回滚、历史账单不受调价/改配方影响、
同账单并发只推进一次、不同账单并发不超扣。本地有 JDK 17 + Maven 时可执行 `mvn test`。
